## 拖放与剪贴板

| --- | --- |
| Chrome 链接拖入并确认 | 直接观测到预览：有效 1、重复 0、无效 0；格式为 `text/uri-list` 与 `text/plain`。确认后任务以暂停状态加入，用户继续后完成 23 字节本地文件。 |
| TXT 投放、取消后重投确认、拒绝 `.url` | 用户手工检查确认通过；未采集文件管理器原生格式名称。 |

跨窗口投放由用户操作；表中「直接观测」与「用户确认」分别标明证据来源。macOS、Linux、其他浏览器和文件管理器组合尚未实机验收。自动化另覆盖容量、取消、晚回调、去重和焦点，不替代原生验收。

### 复现

从仓库根目录执行（PowerShell/Bash 均可）：

```sh
go test -tags dropcheck -c -o .mygo/drop-check.exe ./internal/app
./.mygo/drop-check.exe
```

窗口标题为「拖放验收 · 隔离数据」，数据位于 `.mygo/drop-native-data/`，默认直连并关闭自动开始。

1. 打开 `browser-url.txt` 中的本地地址，拖入 HTTP 链接，检查预览、取消和确认。
2. 投放 `drop-links.txt`，检查重复链接与确认；投放 `unsupported.url`，检查拒绝。
3. 在「设置 → 常规」切换剪贴板提示：关闭时复制；开启后确认不处理旧内容；复制新链接、忽略、重复复制；关闭后再复制新链接。

`formats.log` 只记录拖放格式名称，不含载荷。确认添加与继续下载需分别检查。

从仓库根目录编译并运行隔离程序：

```sh
go test -tags nativecheck -c -o .mygo/tray-check.exe ./internal/app
./.mygo/tray-check.exe
```

该程序单独开启待验收功能，使用本地 HTTP 服务及 `.mygo/tray-native-data/`。检查普通关闭继续下载、托盘恢复/暂停/继续/退出、第二实例恢复；通知样例等待数据目录中的 `complete-notification` 文件出现后完成。

两个验收程序均不使用正常应用数据，不进入普通构建；程序、测试数据和日志位于 Git 忽略的 `.mygo/`。
