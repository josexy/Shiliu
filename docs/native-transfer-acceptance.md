# 原生拖放与剪贴板通知验收

日期：2026-11-22。Windows 11 专业版 23H2（10.0.22631，amd64），Chrome 158.0.8127.36，MyGo 0.10.0。

本次在隔离验收实例中准备本地 HTTP 服务、TXT 和不支持的快捷方式文件。桌面工具只支持窗口内拖动，不能完成浏览器/文件管理器到下载器的跨窗口投放，因此由用户接手手工操作，并确认下列检查项可用。这里区分直接观测证据和用户确认，不把自动化替身测试当作原生验收。

## 验收结果

| 检查 | 结果与证据 |
| --- | --- |
| Chrome 链接拖入添加区 | 直接观测到「拖放链接预览」，有效 1、重复 0、无效 0；接收格式记录为 `text/uri-list` 与 `text/plain`。 |
| 确认后创建任务 | 隔离任务记录显示任务先以暂停状态加入；随后用户继续下载，本地 23 字节文件完成。 |
| TXT 投放、取消后重新投放并确认 | 用户按交接检查项手工验收并确认通过；未单独采集文件管理器的原生格式名称。 |
| 不支持的 `.url` 文件 | 用户确认手工拒绝检查通过；其他未支持类型继续使用粘贴或导入入口，不执行拖入文件。 |
| 剪贴板开关关闭时复制 | 直接观测到没有链接提示、没有自动创建任务。 |
| 开启不读取已有内容、新复制才提示 | 用户按交接检查项手工验收并确认通过。 |
| 忽略后重复复制、关闭后复制新链接 | 用户按交接检查项手工验收并确认通过。 |

用户确认覆盖上述交接清单。TXT 和剪贴板通知部分依赖用户手工验收反馈，不声称由桌面工具独立逐步复现。没有为本次验收修改生产代码；已有自动化仍覆盖容量限制、后台取消、晚回调、去重和焦点等边界。

## 复现入口

从仓库根目录编译隔离程序：

```sh
go test -tags dropcheck -c -o .mygo/drop-check.exe ./internal/app
```

运行 `.mygo/drop-check.exe`，窗口标题为「拖放验收 · 隔离数据」。测试设置和任务位于 `.mygo/drop-native-data/`，与正常应用数据隔离，默认直连且关闭自动开始。`browser-url.txt` 是当次本地服务地址；浏览器打开后可拖动 HTTP 链接，也可尝试不支持的 FTP 链接。`drop-links.txt` 含两个相同的本地下载地址，`unsupported.url` 用于拒绝检查；`formats.log` 只记录拖放格式名称，不记录载荷。

剪贴板检查在「设置 → 常规」切换提示开关，用本地服务下的不同路径作为新链接：关闭时复制，开启后检查没有处理已有内容，再复制新链接、忽略、重复复制，最后关闭开关并复制另一条链接。确认创建与自动下载是分开的动作。

## 验证范围

结论仅覆盖本次 Windows 环境和上述手工检查。macOS、Linux、其他浏览器、其他文件管理器组合尚未实机验收。剪贴板通知不可用时保留手动粘贴，不增加高速轮询；Linux 的通知能力仍取决于桌面环境。托盘后台模式的原生验收不包含在本次范围内，仍保持原有待办与生产入口限制。

隔离程序、运行数据和日志都位于被 Git 忽略的 `.mygo/`，不纳入提交。
