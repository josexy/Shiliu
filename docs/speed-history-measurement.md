# 速度历史的采样与开销

每任务最多保留 120 秒、120 点速度历史，仅存内存。普通 `Snapshot()` 不复制历史，按任务 ID 查询最多复制 120 点。

## 采样规则

- 引擎定时采样，每任务每秒最多一次，与 UI 重绘无关；实际间隔取 Go 单调时钟。
- 速度包含各连接实际接收量和重试流量，不重复增加下载进度；排队、暂停、失败、完成的正常样本为零。
- 首次采样、间隔超过两秒、计数异常或时钟跳变显示缺口，不跨缺口插值；回拨清理未来点。
- 超过 120 秒的点会淘汰；移除任务释放缓冲，退出停止采样，重启后历史为空。

实现见 [history.go](../internal/download/history.go)。

## 测量结果

记录日期：2026-11-22。Windows/amd64、Go 1.27.3、Intel Core i9-14900HX。测试使用虚拟时钟与本地服务，无外部下载。

每任务延迟分配的缓冲为 4872 字节（每点 40 字节，另含索引和采样基线）。1000 / 10000 个缓冲分别为 4,872,000 / 48,720,000 字节，不含任务对象、字符串、分配器开销和临时详情副本。

以下为本机一次短基准，所有任务均填满历史：

| 任务数 | Snapshot 耗时 | 分配字节/次 | 分配次数/次 |
| --- | ---: | ---: | ---: |
| 1000 | 67,473 ns | 598,034 | 1 |
| 10000 | 942,629 ns | 5,922,817 | 1 |

分配来自任务快照切片，不是历史数组复制；结果不代表其他平台的性能保证。
