# Spec Delta

## Purpose

允许用户在关闭主窗口后通过托盘继续管理下载，同时保留可发现的恢复和退出入口。该能力明确平台不可用时的退化行为、后台通知和退出保存语义，避免隐藏窗口导致无法控制任务或丢失进度。

## ADDED Requirements

### Requirement: 用户选择关闭到托盘
系统 SHALL 提供默认关闭且可持久化的“关闭窗口后继续下载”选项，根据运行时托盘可用性隐藏主窗口并继续下载，不按操作系统名单禁用。

#### Scenario: 开启后关闭窗口
- **WHEN** 用户已启用选项、托盘可用并点击窗口关闭
- **THEN** 主窗口隐藏，现有下载及队列继续工作，应用仍持有单实例资源

#### Scenario: 默认行为或托盘失败
- **WHEN** 用户未启用选项，或托盘创建失败、Linux 桌面没有已注册的托盘宿主
- **THEN** 关闭窗口执行正常退出；不可用选项显示原因，不允许进入无法恢复的隐藏状态

#### Scenario: Linux 托盘宿主消失与恢复
- **WHEN** Linux 托盘宿主在运行中消失或重新注册
- **THEN** 后台检测更新选项可用性；宿主消失时恢复隐藏的主窗口，宿主重新注册后允许再次关闭到托盘

### Requirement: 托盘展示概况与控制
系统 SHALL 在托盘提供恢复窗口、活动任务数、排队任务数、合计速度、全部暂停、全部继续和退出入口；概况在状态变化后两秒内更新。

#### Scenario: 隐藏期间控制下载
- **WHEN** 用户在托盘选择全部暂停或全部继续
- **THEN** 行为与主窗口相同，遵守并发和计划限制，菜单概况随之更新

#### Scenario: 恢复隐藏窗口
- **WHEN** 用户选择恢复、点击完成通知、再次启动应用或在 macOS 激活没有可见窗口的应用
- **THEN** 原主窗口显示并获得焦点，任务和选择状态保留，不新建第二个实例

### Requirement: 真正退出完成清理
系统 SHALL 将托盘退出和系统会话结束视为真正退出，取消后台工作、保存任务和设置、释放托盘及单实例资源；关闭到托盘不得拦截这些退出。

#### Scenario: 从托盘退出
- **WHEN** 下载中用户选择托盘退出
- **THEN** 网络及后台工作停止，进度保存，下一次启动可按既有恢复规则继续

#### Scenario: 系统结束会话
- **WHEN** 操作系统通知应用注销或关机
- **THEN** 应用执行正常保存和清理，不显示阻塞确认或再次隐藏窗口

### Requirement: 平台支持可核验
系统 SHALL 明确记录各平台关闭、恢复、退出、通知的实际验证范围；托盘不可恢复的平台不得宣称支持后台模式。

#### Scenario: 发布平台说明
- **WHEN** 发布包含托盘功能的版本
- **THEN** 技术文档记录实际验证范围，并说明托盘不可用时正常退出的行为；缺少实机记录不作为按平台禁用的条件
