# Spec Delta

## Purpose

保留本次运行中用于分析下载失败的关键诊断事件，让用户能够主动导出有限且可分享的故障线索。事件在采集时即排除敏感字段，记录量和导出资源使用均有上限，不引入远程遥测或永久日志。

## ADDED Requirements

### Requirement: 记录必要结构化事件
系统 SHALL 记录任务状态变化、重试序号、HTTP 状态及代理失败类别，并包含事件时间、任务标识和脱敏来源；不得采集响应体、完整请求头或任意未经审查的错误原文。

#### Scenario: HTTP 重试和代理失败
- **WHEN** 本地测试服务返回 503 或代理连接失败
- **THEN** 事件包含相应状态码/错误类别和重试关联，可关联任务，不含请求凭据

### Requirement: 源头脱敏
系统 SHALL 在事件进入缓存之前去除 URL 用户信息、整个查询串、片段、所有自定义头值、代理凭据和本地绝对路径；无法保证安全的错误内容须用结构化错误类别替代。

#### Scenario: 服务端错误回显令牌
- **WHEN** 错误包含 URL 签名、Cookie、Authorization、代理密码或其编码形式
- **THEN** 缓存和导出均不出现这些值，不依赖导出时才清理

### Requirement: 日志容量与性能有界
系统 SHALL 将缓存限制为最多 1000 个事件且编码后不超过 1 MiB，单事件不超过 2 KiB；超限淘汰最旧事件并记录省略计数，诊断记录不得阻塞下载网络工作或持有管理器锁执行文件 I/O。

#### Scenario: 大量重复错误
- **WHEN** 短时间产生超过容量的事件
- **THEN** 缓存保持上限，最新事件可用，省略数量可见，任务仍可及时暂停

### Requirement: 用户主动导出本次日志
系统 SHALL 由用户选择目标路径后导出版本化 JSON，包含应用版本、系统平台、事件和省略计数；导出期间新事件不破坏快照，取消或失败不覆盖原有有效文件。

#### Scenario: 后台导出
- **WHEN** 用户导出时仍有任务产生事件
- **THEN** 导出形成完整一致的有界快照，界面保持响应，新事件继续按缓存规则保存

#### Scenario: 再次启动应用
- **WHEN** 应用退出后重新运行
- **THEN** 上次运行事件不自动加载，不默认写日志文件或发送至远程服务
