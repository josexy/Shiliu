# Design

## Context

动机与范围见 [proposal.md](proposal.md)，行为约束见 [spec.md](specs/download-speed-history/spec.md)。

Item.Speed 为当前聚合速度，fetch advance 已统计字节但 Snapshot 不应增加磁盘或大复制开销；app 详情按 task ID 查当前 Item，`deps.now` 已可替换。没有速度历史模块。

实施顺序：无硬依赖；与单任务/多连接限速通过任务总速度集成。

## Goals / Non-Goals

**Goals:** 在现有包边界内实现上述行为，后台工作可取消、可用替身测试；保留旧数据读取与用户现有默认行为。

**Non-Goals:** 长期统计、历史持久化、图表导出和每个分片单独绘图。

## Decisions

### 1. 状态与职责

在 download 管理器增加独立时钟驱动采样，复用调度 change 若已落地的 Clock 接口，否则在本包新增同一小接口；不依赖 UI 帧率。以单调经过时间和累计实际网络字节差计算速率，最多每秒一次，重试实际流量计入速度但 Done 不重复累计。

### 2. 核心执行方式

每任务固定长度 120 环形缓冲，查询只复制指定 ID 的小段历史；Snapshot 不附全部采样。惰性创建缓冲，非活动时生成有界零样本，全部旧样本过期后可折叠空历史；Remove 清理，Shutdown 停止定时器。

### 3. 一致性与边界

相邻采样间隔超过两秒或时钟异常标记缺口，首次等待有效差值；时间显示用墙钟但速率用单调时长。任务连接数不影响采样数量，各连接累加到统一计数器，避免重复汇总。

### 4. 生命周期与交互

详情使用原生绘图控件绘制折线，绘制回调仅读不可变历史副本，坐标轴和单位保留文本及无障碍描述；style.go 中定义曲线与网格颜色，暂停/缺口明确，960×640 下可滚动。

### 5. 集成与验证

历史不进入 Record/settings，不为图表引入第三方依赖。用 fake clock 覆盖采样上限和休眠，数据量基准确认普通 Snapshot 不复制历史。

## Risks / Trade-offs

- 大量任务仍有 O(任务数×120) 空间 → 固定容量、惰性分配和移除释放，性能测试记录实际内存。
- 时钟跳变导致异常峰值 → 单调间隔与缺口规则，非法值不进入曲线。

## Migration Plan

无需数据迁移；启动后历史为空，已完成文件不为补历史重新读取。关闭功能直接停止采样。

先执行针对性用例，再执行全量测试与 MyGo 静态检查；界面变化检查两套主题、960×640 和 125% 缩放。平台服务以 deps 替身测试，原生行为另记真实验证范围。发布后更新 README 与 roadmap；本提案阶段不变更应用版本。
