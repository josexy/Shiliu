# Design

## Context

动机与范围见 [proposal.md](proposal.md)，行为约束见 [spec.md](specs/file-integrity-verification/spec.md)。

`fetch.go/finalize` 完成后发布 StateCompleted 并通知，Item 没有摘要状态；RefreshFiles 已异步检查缺失。详情和高级表单已有持久草稿与异步 generation 模式。标准库足以完成 SHA-256。

实施顺序：无硬依赖；多连接分片完成后可复用本能力。

## Goals / Non-Goals

**Goals:** 在现有包边界内实现上述行为，后台工作可取消、可用替身测试；保留旧数据读取与用户现有默认行为。

**Non-Goals:** 数字签名验证、自动查询摘要和自动删除/重新下载不匹配的文件。

## Decisions

### 1. 状态与职责

增加 ExpectedSHA256、VerificationState、实际摘要、上次校验时间及文件大小/修改时间等元信息。传输 State 不新增 checking 值，以免影响并发、过滤及完成回调；完成即释放网络槽位，校验队列独立串行运行，限制磁盘压力。

### 2. 核心执行方式

校验 worker 使用 context、固定 256 KiB 缓冲和 crypto/sha256，块间检查取消；读取前后比较文件身份/大小/修改时间，拒绝明显变化。用 task generation + expected digest + path 绑定结果，提交前再检查任务仍存在且版本相符。

### 3. 一致性与边界

预期摘要变化先取消旧工作并递增 generation；清空时回到未配置。用户取消后不自动重启，重新校验显式入队；删除和 shutdown 取消并等待文件句柄释放，避免 Windows 删除失败。

### 4. 生命周期与交互

持久化预期值与历史结果，仅作“上次结果”；重启对已完成且配置摘要的任务回到待校验，需要用户重新执行以确认当前文件。mtime 不能防范所有同大小替换，故不把历史结果当本次可信结论。

### 5. 集成与验证

下载完成通知明确只代表传输，校验通过/失败使用单独 UI 状态和可选结果通知。详情可取消、重新校验，错误经现有诊断脱敏；不自动删除用户文件。

## Risks / Trade-offs

- 哈希完成时文件被替换 → generation 和前后身份检查，无法保证不受恶意同时写入时说明校验时间点语义。
- 大量大文件争用磁盘 → 单独串行校验队列，取消优先，网络并发不受影响。

## Migration Plan

旧记录无摘要字段即不校验；升级不自动对旧文件扫盘。新增校验结果向后可忽略，回滚仅失去校验展示，文件路径和下载状态保持。

先执行针对性用例，再执行全量测试与 MyGo 静态检查；界面变化检查两套主题、960×640 和 125% 缩放。平台服务以 deps 替身测试，原生行为另记真实验证范围。发布后更新 README 与 roadmap；本提案阶段不变更应用版本。
