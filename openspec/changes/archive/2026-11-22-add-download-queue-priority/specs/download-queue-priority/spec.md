# Spec Delta

## Purpose

让用户调整等待下载任务取得执行槽位的先后顺序，并在暂停、删除和应用重启后保持该顺序。调度优先级独立于列表及卡片的视觉排序，确保用户改变展示方式时不会意外改变下载行为。

## ADDED Requirements

### Requirement: 排队任务可调整顺序
系统 SHALL 为处于排队且尚未取得执行槽位的任务提供置顶、上移和下移，移动以完整的可调度队列为参照，并展示队列位置。

#### Scenario: 置顶等待任务
- **WHEN** A 正在运行，B、C 依次排队，用户将 C 置顶
- **THEN** A 继续运行，下一空闲槽位交给 C，然后是 B

#### Scenario: 边界与并发状态变化
- **WHEN** 用户上移首项、下移末项，或提交时目标已开始/被删除
- **THEN** 操作不破坏顺序；边界操作无变化，已不可调项不被重新启动或抢占

### Requirement: 调度与展示排序独立
系统 SHALL 按独立队列顺序选择任务，列表的名称、大小、时间排序以及搜索筛选不得改变它。

#### Scenario: 过滤视图中移动
- **WHEN** 用户隐藏部分任务并移动可见的排队任务
- **THEN** 只按完整队列执行相邻移动，显示更新后的真实队列位置，其他视图排序保持原配置

### Requirement: 顺序持久化与旧记录兼容
系统 SHALL 保存调度顺序；旧记录无顺序字段时沿用记录顺序，新任务排在已有任务之后，删除不改变余项相对顺序。

#### Scenario: 重启后继续
- **WHEN** 用户调整顺序并重启，再继续原暂停任务
- **THEN** 这些任务按保存的相对顺序启动，旧记录仍可正常读取且默认保持暂停

#### Scenario: 暂停和删除
- **WHEN** 排队任务暂停后再次继续，另一项被删除
- **THEN** 继续的任务保留原有排序位置，其他任务的相对次序保持不变

### Requirement: 并发上限始终生效
系统 SHALL 只在有空闲槽位时启动排队任务，队列调整不得取消或重新连接运行中的任务。

#### Scenario: 并发已满时连续调整
- **WHEN** 并发数为二且已有两个任务运行，用户多次调整队列
- **THEN** 活动任务数不因排序而增加，空位出现时按最后一次有效顺序启动
