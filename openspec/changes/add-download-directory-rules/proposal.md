# Proposal

## Why

当前只有全局默认目录和单任务覆盖，批量下载仍需手动分类。按扩展名或域名匹配目录可以减少重复选择，同时保留已有路径和冲突保护。

来源：按需穿插，对应 [迭代计划](../../../docs/roadmap.md)。

## What Changes

- 设置中管理有序且可启停的扩展名/域名规则，首个匹配项决定新任务目录。
- 显式单任务目录优先，其次分类规则，最后全局默认目录；提供匹配结果预览。
- 规则只影响新任务，持久化并兼容旧设置，目标目录不可写时明确报错。

本次不包含：移动已有文件、按文件内容识别类型、重定向后改目录和正则表达式规则。

## Capabilities

### New Capabilities

- `download-directory-rules`：分类与目录规则的用户行为、兼容性和验收约束。

### Modified Capabilities

无。生成提案时主规格目录没有已有 capability，本 change 新增上述独立规格，不重建第一阶段基线。

## Impact

`internal/settings` 规则结构与规范化、新增独立目录规则解析模块或文件、`internal/download` 新建路径选择、`internal/app` 规则设置及测试。

实施依赖：无硬依赖；批量导入、拖放与剪贴板确认添加均走相同的新建路径。

实现完成后更新 README 的功能与限制，以及 roadmap 的对应进度；本轮仅产出规划，不勾选已实现项。
